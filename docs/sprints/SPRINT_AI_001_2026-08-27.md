# AI-001 — BYOK Anthropic sécurisé

## Statut

`REVIEW_REQUIRED`

## Objectif utilisateur

Permettre à chaque utilisateur de fournir sa propre clé Anthropic et de choisir
un modèle réellement disponible, sans exposer le secret ni dégrader les notes,
les images ou la PWA existantes.

## Périmètre

### Secret

- mode session : clé conservée uniquement en mémoire jusqu'au rechargement ;
- mode synchronisé : clé chiffrée par Supabase Vault et accessible uniquement
  aux fonctions serveur ;
- aucune clé dans `localStorage`, IndexedDB, Git, réponse JSON ou journal ;
- remplacement, test et suppression explicites.

### Modèles et résumé

- catalogue chargé depuis `/v1/models` avec la clé de l'utilisateur ;
- identifiant de modèle validé et préférence synchronisée en mode persistant ;
- prompt, taille d'entrée et sortie bornés côté serveur ;
- erreurs Anthropic normalisées sans corps amont ni secret dans les logs.

### Protection

- session Supabase requise avant tout détail de configuration ;
- quota persistant et atomique par utilisateur ;
- réponses IA et paramètres en `Cache-Control: no-store` ;
- tables, fonctions Vault et RPC interdites à `anon` et `authenticated`.

## Critères de sortie

- migration forward-only prévisualisée puis appliquée sans modifier les tables
  de notes et d'images ;
- flux session et synchronisé testés ;
- sélection dynamique du modèle et absence de persistance navigateur vérifiées ;
- 401 sans session, 428 sans configuration, 429 au quota et erreurs fournisseur
  sûres couverts ;
- lint, tests, build et audit npm verts ;
- PR fusionnée après `Quality gate`, Vercel `READY` sur le SHA exact ;
- recette de production exclusivement synthétique et nettoyage contrôlé.

## Rollback

L'ancien déploiement ignore les nouvelles tables. Un rollback applicatif peut
donc réassigner le dernier déploiement sain sans supprimer la migration. Les
objets SQL restent en place ; toute correction de schéma est forward-only.

## Preuves avant PR

- migration production prévisualisée, corrigée puis appliquée atomiquement ;
- historique distant `20260827094500` enregistré ;
- audit SQL : 9/9 ; cycle Vault factice avec rollback et zéro résidu ;
- `npm run validate` : 59/59 tests, lint et build verts ;
- audit npm élevé : zéro vulnérabilité ;
- smoke synthétique : 30 contrôles et nettoyage vérifié ;
- recette UI locale : menu, palette, modale, modes et effacement du secret.

La clôture `DONE` exige encore la PR, le `Quality gate`, Vercel `READY`, le SHA
exact et la recette synthétique post-déploiement.

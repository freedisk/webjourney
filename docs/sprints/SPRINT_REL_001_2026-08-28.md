# REL-001 — Version, À propos et mises à jour

## Statut

`DONE`

## Constat

Capsule disposait d'un historique technique et d'icônes PWA, mais l'interface
ne permettait pas d'identifier précisément la version chargée sur un appareil.
Une PWA Safari peut rester ouverte plusieurs jours ; sans build visible, un
écart avec la production est difficile à diagnostiquer.

## Objectif utilisateur

Afficher une identité de livraison compréhensible, consulter les dernières
évolutions et vérifier explicitement si l'application chargée correspond au
build actuellement servi en production.

## Périmètre

- baseline publique SemVer `1.0.0` dans `package.json` et le lockfile ;
- SHA Git comme identifiant de build, affiché sur sept caractères ;
- date ISO réelle calculée une fois pendant le build ;
- footer compact et responsive, cliquable vers **À propos** ;
- accès depuis le menu et la palette `Ctrl/Cmd+K` ;
- dialogue accessible avec identité, changelog utilisateur de trois jalons et
  états de vérification explicites ;
- endpoint public `/api/version`, dynamique et non mis en cache ;
- rechargement volontaire avec contrôle préalable du service worker ;
- aide de dépannage, tests, guide de versioning et documentation de release.

## Hors périmètre

- compteur numérique externe ou base de données de releases ;
- mise à jour automatique, rechargement imposé ou notification push ;
- contenu de note, image, compte, secret ou télémétrie dans le contrôle ;
- nouvelle variable obligatoire, dépendance ou migration Supabase ;
- mécanisme natif App Store/TestFlight.

## Décisions

- La version décrit le produit ; le build décrit le commit effectivement
  construit. Un redéploiement identique conserve donc le même build, avec une
  nouvelle date de construction.
- `VERCEL_GIT_COMMIT_SHA` est utilisé sur Vercel ; Git local puis `local` sont
  les replis sûrs. Seules les trois métadonnées explicitement non sensibles
  sont injectées dans le bundle.
- La vérification reste manuelle et appelle l'alias courant en `no-store`.
  Aucun appel réseau n'est ajouté au démarrage ou dans le footer.
- La route `/api/version` reste exclue du service worker comme toutes les routes
  `/api/`. Une absence de réseau conserve l'application chargée et produit un
  message actionnable.

## Critères de sortie

- version, build et date cohérents dans le dialogue ;
- footer complet sur desktop/iPad et court sur iPhone, sans recouvrir la
  navigation basse ni réduire les cibles tactiles ;
- ouverture depuis le menu, la palette et le footer, fermeture `Échap` et focus
  restitué ;
- contrôle manuel : états attente, à jour, nouvelle livraison et indisponible ;
- réponse `/api/version` en `200`, JSON strict, `no-store` et `nosniff` ;
- aucune note, image, clé IA, identifiant de compte ou variable secrète exposée ;
- lint, tests, build et audit npm élevé verts ;
- PR protégée fusionnée, Vercel `READY` et smoke public conformes.

## Validation locale

- lint propre ;
- **105/105 tests** dans dix-huit fichiers ;
- build Next.js 16.3.3 réussi avec `/api/version` dynamique ;
- smoke HTTP **7/7** : accueil, statut et trois champs, SemVer, SHA complet,
  date, `no-store` et `nosniff` ;
- `npm run validate` complet vert et audit npm élevé à zéro vulnérabilité ;
- aucune modification Supabase, variable Vercel, donnée ou dépendance ;
- preview Vercel `READY` sur le commit `595987b` et smoke distant **8/8** :
  JSON version strict, SemVer, SHA complet, date ISO, manifest, mode standalone,
  service worker et page de connexion ;
- PR #24 fusionnable sans conflit avec les deux contrôles `Quality gate` et le
  contrôle Vercel terminés en succès ;
- recette visuelle locale reportée à la preview HTTPS : le navigateur intégré a
  conservé sa page d'erreur après une connexion tentée avant le démarrage du
  serveur et interdit ensuite la navigation depuis cette page. Le smoke HTTPS
  a donc été exécuté via le canal authentifié de la CLI Vercel, sans contourner
  cette politique.

## Rollback

Réassigner le dernier déploiement Vercel sain. L'ancien client ignore la route
supplémentaire et le footer ; aucune donnée, migration ou configuration n'est à
restaurer.
